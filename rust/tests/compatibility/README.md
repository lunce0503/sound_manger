# C# DSP golden fixtures

The 40 checked-in `.smg` files are generated by the **current working-tree**
`SoundManager.Core` implementation, including its latency recovery changes.
They contain synthetic PCM only: no captured audio, identities, pairing keys,
addresses or machine-specific settings. Generation runs every scenario twice
and rejects non-deterministic results.

Coverage: 8/44.1/48/192 kHz × mono/stereo × PCM16/float32; five EQ presets and
live EQ changes; six directions; mute/volume changes; stereo preservation;
startup and rebuffering; overflow; latency trims at four rates; large 60/200 ms
output requests; non-finite/out-of-range floats; clipping; ten simultaneous
sources; and 100 consecutive streaming packets.

Run from the repository root:

```powershell
dotnet build tools/SoundManager.Golden -c Release
dotnet tools/SoundManager.Golden/bin/Release/net10.0/SoundManager.Golden.dll --verify rust/tests/compatibility/fixtures
```

After deliberately changing the baseline, review the C# behavior and regenerate
with `--write` instead of `--verify`. Review the fixture diff and source hashes.
The manifest uses SHA-256 and normalizes C# source line endings to LF. It has no
timestamps or generated session UUIDs. Never regenerate automatically in CI.

The Rust integration test replays the same packets and settings. Each rendered
sample must be finite and within **2 × 10⁻⁵ absolute amplitude** of C#.
Buffered milliseconds must match within 10⁻⁹; all recorded counters must match
exactly. This is numerical compatibility, not a hardware latency measurement.

## SMG1 file format

All numbers are little-endian. `f32`/`f64` are IEEE-754; booleans are one byte.

1. Four magic bytes `SMG1`.
2. `u32 sourceCount`, followed by `sourceCount` format triples:
   `u32 sampleRate, u32 channels, u32 encoding` (`0` = PCM16, `1` = float32).
   Sources start with default settings, in declaration order.
3. `u32 eventCount`, followed by tagged events:

| Tag | Payload |
| --- | --- |
| `0` push | `u32 sourceIndex, u32 byteCount, byte[byteCount] PCM` |
| `1` render | `u32 sampleCount, f32[sampleCount] expectedOutput, u64 clippedSamples`, then the per-source state below |
| `2` configure | `u32 sourceIndex, f32 volume, f32 azimuth, bool spatial, bool muted` |
| `3` mix | `f32 masterVolume, f32 bassDb, f32 trebleDb, f32 presenceDb` |

Per-source state after each render, in declaration order:
`f64 bufferedMs, u64 droppedFrames, u64 underruns, u64 receivedPackets,
u64 latencyTrims, u64 latencyTrimmedFrames`.

Session IDs, wall-clock diagnostics and display names are intentionally excluded
from binary fixtures. Display-name validation is covered by Rust behavior tests;
wire/persistence compatibility belongs to Phase 2.
